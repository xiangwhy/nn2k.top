> **一个输入框查全部** — 账单、到货、采购记录三种 Excel 表格丢进去自动入库，之后按运单号 / 唛头 / 人员 / 日期查，列可以自己勾。

## 项目背景

自从有了 AI，把很多以前做不了的想法慢慢做出来了 — 这个不算「以前做不了」，但以前**做得很难看**：一堆格式不一样的 Excel 散在各处，要查一个运单号，得知道它在哪个文件里、翻到第几行、把几个表的信息拼起来。

Excel 打开、Ctrl+F、翻页、横向对比 —— 一件事做熟了要五分钟，而且新人根本不知道该翻哪个文件。所以做了个库，把表全导进去，查询这件事本身变成一步。

## 我做了什么

单文件 Python 服务：**pandas 读表 → SQLite 存 → 标准库 HTTP 起服务 → 一个网页查**。没有 Flask、没有 ORM、没有前端框架。

### 三种表，一条管道

源文件有三种形态，字段不同但大量重合：

- **账单表** —— 前面有八行公司抬头，第 9 行才是表头，得跳过去
- **到货表** —— 第 1 行就是表头
- **采购记录** —— 第 1 行表头，但同一份文件里可能有**十二列和二十六列两种 schema**，而且一张文件里一个 sheet 算一批货

文件名的信息也要用：类型（账单/到货/采购记录）、件数、日期都藏在文件名里，而且**位置不固定**（`XXX-N件M-D账单` 和 `XXX-账单N件M-D` 都出现过），只能全文找关键词。

采购记录按 sheet 拆开入库，源文件标识记成 `文件名::sheet名`，这样单个 sheet 被改名或删除时才不会误伤同文件的其他 sheet。

### 增量导入：内容指纹

导入要能反复跑而不产生重复数据。做法是给每个源文件算 **sha256 内容指纹**：

- 文件名相同、内容没变 → 跳过
- 文件名相同、内容变了 → **先解析成功，再删旧行**，然后重导

「先解析成功再删旧行」这条是修出来的：早先的版本先删后导，文件一旦解析失败（比如 Excel 半路损坏），旧数据已经没了 —— 而源文件可能已经是唯一副本。

同一条原则贯穿整个导入流程：**读不出来的源文件，它的旧行一律留着**，不删也不当孤儿清理。孤儿清理只处理「源文件确实被删了 / sheet 改名了」的情况，而且只在当前导入目录范围内做，跨目录不动。

### 列名规范化

三种表的列名写法不统一 —— 带换行、带全角括号、带单位后缀（`长(CM)` / `总重量/KG` / `木架费150/m³(RMB)`）。归一化逻辑（去空白、去换行、去括号、去单位）必须**两边共用**：映射表的 key 也要先归一化，否则那八列永远导不进来 —— 这个 bug 表现为「列都在表里但全是空值」，排查花了一会儿。

同理，脏数据清理规则都限定在 `来源='账单'` 范围内 —— 采购表普遍缺时间字段，不限定就会把整批采购行当垃圾删掉。

### 查询：一个输入框

一个输入框搞定大部分查询：输运单号或唛头，`↑↓` 翻历史，空着就是最近 100 条。旁边一个人员下拉（从库里统计出来的），再旁边一个列选择器决定这次显示哪些列。

查询背后是关联子查询 + `EXISTS`，一开始**一个索引都没有**，每次查都在扫库：

```
覆盖索引加上去：最大的一组 21.2 秒 → 423 毫秒
第二大的那组   7.3 秒 → 2.0 秒
```

索引建在 `(所属人员, 运单号)` 上，让子查询只走索引不回表。剩下最慢的那组仍然要几秒 —— 那不是索引能救的，要改查询形状，是后面的事。

### SQL 控制台：只读，两道保险

给了一个能直接写 SQL 的入口（查东西比猜筛选器快），但库里是原始业务数据，不能让人乱写。

只读做了两道独立的保险：

1. **语句白名单** —— 首 token 只允许 `SELECT / WITH / PRAGMA / EXPLAIN`，并且整句不允许出现分号（防止 `;` 后面追加写语句）。
2. **SQLite authorizer** —— 白名单只看首 token，`WITH ... DELETE/UPDATE/INSERT` 能绕过去；而 CPython 只对 `insert/update/delete` 开头的语句隐式开事务，`WITH` 开头的跑在 autocommit 下，执行完立即提交，`close()` 也回滚不了。所以在 SQL 层再兜一道。

另外加了查询结果上限（1000 行），超了提示导出 CSV。

### 顺手做的两件事

- **运单追踪** —— 输入运单号，后端抓承运商的公开追踪页，正则提取船名、运输方式和每一段轨迹时间线；抓不到就明说「无查询结果」，不装作有数据。
- **手机能用** —— 手机端改成卡片流（表格横向拖在手机上没法看）、结果行可复制、iOS 点输入框不再自动放大页面。

### 部署

Docker 单容器，**代码用 bind mount 挂进去**，改完代码不用重建镜像 —— 改代码是常态，重建一次几分钟。

部署脚本做成了幂等的：

- 依赖没变就复用已有镜像（那台机器连不上镜像仓库，重建会卡在拉基础镜像上，所以要避免无谓重建）
- 数据文件**只在远端没有时才传** —— 增量导入跑在服务器上，本地那份永远追不上，无条件覆盖会把线上的更新抹掉
- 传源文件用 `tar` over ssh 而不是 rsync：远程不一定装了 rsync，而且中文、空格文件名必须用 `--null` 传递才不会出错

## 已知未解 / 显式没做

- ❌ **最慢的那组查询仍要几秒** —— 索引救不了，是查询形状的问题（关联子查询在千万级前缀下没走成覆盖），要改成别的查法。
- ❌ **到货表目前不导入** —— 解析函数写了，但导入路径上被跳过（会跟账单表的列语义冲突），先留空。
- ❌ **单进程 `ThreadingHTTPServer`** 只够自用，多用户并发要换。
- ❌ **Excel 解析的容错靠"解析出空数据就跳过"兜** —— 表头被挪动时 `read_excel` 不报错，只读出一堆空列，靠额外的校验函数识别出来。
